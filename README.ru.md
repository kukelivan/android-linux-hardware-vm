# Android Linux Hardware VM

**Полноценный Linux и Docker на Android через аппаратную виртуализацию, без замены штатного загрузочного ядра Android.**

[English](README.md) · [Пять подходов](docs/APPROACHES.md) · [Подготовка](docs/QUICKSTART.md) · [Ограничения](docs/LIMITATIONS.md)

Linux-гость может стать основной рабочей средой для разработки, серверных приложений и командной строки: собственное ARM64-ядро, systemd, apt, постоянные диски, SSH и Docker. Android остаётся работающей системой, управляющей оборудованием телефона.

## Зачем нужна виртуальная машина

Root не добавляет в ядро отсутствующие возможности. Chroot меняет видимую файловую систему, но использует ядро Android; контейнеры тоже зависят от ядра своего хоста. Если набор namespaces, cgroups, overlayfs и netfilter неполон или ограничен, одного Debian-окружения недостаточно.

Аппаратная VM переносит Linux на **собственное гостевое ядро**, в которое можно включить нужные функции. Поэтому ограничения Android-ядра для Docker и многих Linux-приложений обходятся внутри гостя. Это полноценная Linux-система, а не только способ запустить контейнер.

При этом «штатное ядро» не означает отсутствие привилегированных изменений: нужны настоящий root и совместимые модули, загружаемые в работающее ядро Android. Замена boot-ядра и перепрошивка телефона проектом не выполняются.

## На чём основан проект

Используется Gunyah — аппаратный гипервизор, доступный на поддерживаемой платформе Qualcomm через Android-драйвер и crosvm. Название гипервизора — техническая деталь, а назначение проекта — Linux с аппаратной виртуализацией на телефоне.

Референсный порт: ASUS ROG Phone 8 / AI2401, Android 16, 12 ГБ ОЗУ, Android-ядро `6.1.112-android14-11-g76e6db6a5f77-ab13748698`. Совместимость проверяется по release ядра и BTF. Наличие Snapdragon само по себе ничего не гарантирует: нужны подходящие firmware, `/dev/gunyah`, ABI и версия crosvm. Проект не обещает работу на любом Android.

## Пять вариантов

| Профиль | ОЗУ гостя | Что добавляется | Основное ограничение |
|---|---:|---|---|
| `classic` | 1024 МиБ | Модуль резерва, защитный shim | Небольшой фиксированный объём |
| `split` | 1664 МиБ | Два основных parcel и адаптер меток | Зависимость от внутреннего ABI RM |
| `shared` | 4096 МиБ | Подготовка backing и небольшие shared-parcel | Вся память резервируется до загрузки |
| `custom-fixed` | 3072 МиБ | Собственное гостевое ядро | Поддержка сборки ядра, память фиксирована |
| `grow` | 256 → 4096 МиБ | Runtime SHARE, MEM_ACCEPT, hot-add и агент | Возврат памяти только при выключении |

Для переменной нагрузки выбран **`grow`**: маленький начальный объём, добавление блоков по 128 МиБ, сохранение резерва Android и освобождение всех ресурсов при штатном выключении. 4 ГиБ — реализованный и проверенный предел политики, а не найденный аппаратный максимум.

## Запуск

Это исходники референсного порта, а не универсальный APK. В репозитории нет личных дисков, готовых приватных образов или ключей. Сначала нужны совместимые host-модули, гостевое ядро, shims и свежий Debian-образ: [инструкция сборки](docs/BUILD.md), [точный порядок](docs/QUICKSTART.md).

```sh
./droidvm configure \
  --android-rootfs /data/data/com.termux/files/usr/var/lib/proot-distro/containers/debian/rootfs
sudo python3 scripts/create-rootfs.py
sudo python3 scripts/make-initrd.py
sudo ./droidvm doctor --profile grow
sudo ./droidvm up grow
sudo ./droidvm ssh
sudo ./droidvm exec 'uname -a; docker info'
sudo ./droidvm down
```

Внутри гостя обычные Linux-команды и Docker. Данные сохраняются в rootfs и отдельном `/workspace`. `DROIDVM_STATE` выбирает локальный каталог состояния; по умолчанию `/var/lib/android-linux-hardware-vm`.

## Границы возможностей

Linux может быть основной **рабочей** средой, но не заменяет Android как систему управления телефоном. Проект не предоставляет прямой вывод на экран, GPU/touch/camera/modem passthrough, вложенную виртуализацию, миграцию VM или готовый ускоренный рабочий стол. GUI через удалённый доступ — отдельная настройка.

Root и `--disable-sandbox` означают, что нужны доверенные гостевые образы. Из этого запуска нельзя делать вывод о защите от вредоносной гостевой ОС или confidential computing.

Рост памяти выполняется только после резервирования backing, принятия parcel гипервизором и подключения RAM в Linux. Parcel ограничен 512 SG-сегментами; Android сохраняет резерв `max(2048 МиБ, 20% MemTotal) + 512 МиБ`. Живое уменьшение не реализовано: память возвращается после выключения. Нельзя принудительно выгружать модули, убивать зависший VMM или автоматически перезагружать устройство.

Реализация расширения использует исходный restricted DMA pool для virtio; карта RAM в crosvm на ходу не расширяется. Поэтому произвольные устройства, миграция и passthrough требуют отдельной реализации.

[Проверка на свежем публичном Debian-образе](docs/REFERENCE.md).
